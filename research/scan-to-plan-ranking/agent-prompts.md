# エージェント指示文

共通の禁止事項（全フェーズに前置きすること）:

- 自分の記憶から製品情報を書かない。取得できた一次情報のみ書く
- fetch に成功していない URL は書かない
- 確認できない項目は推測せず `unknown` を残す
- ベンダーの記述は事実ではなく主張として `claim_type: vendor_doc` で記録する
- 点数・順位・おすすめ度を付けない。事実を集めるだけ

---

## フェーズA: 発見（5並列）

出力は **製品名 + 公式URL + 型分類(A/B/C/D)** のみ。評価は書かない。
重複は気にせず集める。名寄せは集約側で行う。

### A-1 モバイルアプリストア
iOS App Store を日本・米国・ドイツ・英国ストアで横断。LiDAR 対応を明示している
室内スキャン / 間取り作成アプリを列挙。ストアの「関連アプリ」も1階層たどる。

検索語（日本語）: 間取り 作成 LiDAR / 部屋 スキャン 図面 / 現地調査 採寸 3D /
室内 3Dスキャン 平面図 / リフォーム 採寸 アプリ
検索語（英語）: LiDAR room scan floor plan / scan to CAD app / as-built floor plan iPhone /
interior 3D scan DXF / measure room LiDAR export

### A-2 国内の業務SaaS内蔵機能
リフォーム・工務店向けの施工管理／見積／現調 SaaS が、スキャン機能や
間取り自動作成機能を持っていないか。単体アプリ検索では出てこないため独立担当を置く。

### A-3 空間計測プラットフォーム
Matterport 系の空間キャプチャ製品と、その**図面化オプション / スキーマティックフロアプラン**。
ここは B型（クラウド処理で図面が返る）の主戦場。

### A-4 CAD・点群経由
CAD ベンダーが公式に公開している連携モバイルアプリ一覧、および
点群 / メッシュ → DXF 変換サービス。C型の母集団。
レーザー距離計メーカーの公式対応アプリ一覧も網羅性が高いので当たる。

### A-5 作図代行と検証文献
スキャンデータを送ると人が作図して納品する D型サービス。
あわせて、iPhone/iPad の LiDAR 精度を実測比較した**学術論文・公的機関の検証**を収集する
（測定条件と誤差の数字があるものだけ。レビュー記事は不可）。

停止条件: 2ラウンド連続で新規製品ゼロ。

## フェーズB: 立証（1製品 = 1担当）

`schema.json` の **fields の全キーを埋める**。1つも飛ばさない。
各値は value_object の形（value / claim_type / source_url / quote / fetched_at / confidence）。

情報が載っている場所の目安（ストアページだけ見て終わらせないこと）:

| 項目 | 見る場所 |
|---|---|
| 価格体系・実質単価 | 公式の Pricing ページ。**プラン比較表の脚注**にスキャン単価が隠れている |
| 出力形式 / DXF 可否 | Pricing のプラン比較表、ヘルプセンターの Export 記事 |
| 面積の自動算出 | ヘルプセンター / サポート記事。トップページには載っていないことが多い |
| 待ち時間 | ヘルプセンターの FAQ、またはサポート記事の「処理には◯分」 |
| 端末要件 | App Store の「互換性」欄（構造化データ＝事実） |
| 最終更新日 | App Store の「新機能」欄（構造化データ＝事実） |
| ひとり運用 | 公式のワークフロー動画・チュートリアル |

出力: `evidence/<product>.json`

## フェーズC: 精度の根拠収集

**ベンダーのサンプル図面は使わない。** 営業用に人が整えたものであり、
それを見ても作り手の技量を測っているだけで、自動出力の実力を示さない。

集めるのは「人が手を入れていない自動出力が、実際にどれだけ合っているか」の測定データ。

- Apple RoomPlan の精度を実測比較した学術・公的検証
  （多くのアプリが RoomPlan を土台にしているため共通の基礎になる）
- 実務者・業界紙による実測比較で、測定条件と数値があるもの
- 自動出力がどこで失敗し、どれだけ手直しが要るかの一次的な記録
- 日本固有の要素（和室・押入・下がり天井・梁・引き戸・段差）での挙動
- 壁芯か内法か（見積の面積が丸ごとずれるため精度以前の論点）

ベンダーの精度表記は `claim_type: vendor_claim` として記録し、測定値と混ぜない。

Pricing ページのスナップショットは引き続き取得日つきで保存する。

## フェーズD: 反証（3主張のみ・製品ごとに独立担当）

肯定ではなく**崩しにいく**。迷ったら「未確認」に倒す。

1. **「DXF が出せる」** — 本当にどのプランで出せるか。無料版では出ないのでは。
   追加課金はないか。出力される DXF は 3D メッシュではなく2D平面図か
2. **「面積が自動で出る」** — 床だけではないか。壁面積の開口部控除は本当に自動か。
   書き出せるのか、画面表示だけか
3. **「この価格で使える」** — スキャン単価・㎡単価・年契約縛り・
   最低ユーザー数がないか。1戸あたりの実質額はいくらか
