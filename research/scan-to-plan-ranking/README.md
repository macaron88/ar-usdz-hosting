# スキャン→図面 アプリ独自ランキング 調査設計

最終更新: 2026-08-27

## 目的

リフォーム現況調査において、**現場担当者がひとりでスキャンし、見積に使える図面と数量が
手間なく手に入る**アプリを、一次情報と自前の実測にもとづいて順位付けする。

他者のランキングは転載しない。製品の発見（母集団づくり）にのみ二次情報を使う。

## 確定した前提条件

| 項目 | 決定 |
|---|---|
| 図面の用途 | **① 見積用**。面積と主要寸法が合っていればよい。施工図・申請レベルは不要 |
| 出力形式 | **足切りにしない**。DXF でも BIM でも可（BIM から平面図は起こせる）。出力可能な全形式を種類別に一覧化して報告する |
| 現場体制 | **ひとりスキャン**。補助者・三脚・外部機器を必要としないこと |
| 端末 | **LiDAR 前提**（iPhone Pro / iPad Pro 系）。LiDAR を使わない製品は参考枠 |

この4つが順位そのものより先に効く。特に「用途①」は評価の重心を精度から工数へ移す。

## 順位の決め方

精度と手間を足し算しない。**精度は足切り、順位は工数**で決める。

### 足切り（Gate）

すべて満たさないものは順位表に載せない（参考枠に落とす）。

1. LiDAR を計測に使用する（iPhone / iPad Pro で動作）
2. **ひとりで完結できる**（三脚・補助者・外部スキャナが必須でない）
3. 精度が見積用途に耐える（下記の実測基準）

出力形式は足切りに含めない。種類を網羅的に一覧化して併記する。

精度の足切りライン（実測フェーズで判定・数値は運用しながら調整可）：

- 床面積の誤差 **±3% 以内**
- 主要寸法（部屋の内法、開口部幅）の誤差 **±50mm 以内**
- 同じ部屋を2回スキャンした際の**再現性のばらつきが上記の範囲内**

用途①では点群のミリ精度は問わない。「拾った数量が見積を壊さないか」だけを見る。

### 主KPI（順位を決める唯一の数値）

```
1戸あたり人的工数（分）= 撮影時間 + 修正時間
```

- **待ち時間は別掲**（クラウド処理中は人が拘束されないため、工数には加算しない）
- 修正時間は「見積に使える状態にするまで」。図面としての美しさは問わない
- 修正を**現場担当者本人ができるか / CAD が分かる人が必要か**をフラグで持つ

### 併記する列（順位には使わないが必ず出す）

計測精度 / 図面精度 / **出力可能形式の全リスト** / 費用（体系と実質単価） /
日本での利用条件 / 端末要件 / 待ち時間 / オフライン可否

## 用途①で最重要になる機能：面積の自動算出

見積用途では、図面そのものより**数量が自動で出るか**が工数を支配する。
以下が自動算出されるかを全製品で確認する。

- 床面積（部屋別）
- 壁面積（クロス用。開口部の控除が自動か）
- 天井面積
- 開口部（ドア・窓）の寸法と数
- 数量表の書き出し形式（CSV / Excel / PDF）

ここが自動化されているかどうかで、後工程の工数が桁で変わる。
「図面は出るが面積は自分で拾う」製品は、DXF が出ても順位は下がる。

## 母集団の定義

出力形態で4分類し、C型・D型も必ず母集団に入れる（単体アプリだけを見ると選択肢を落とす）。

| 型 | 中身 | 扱い |
|---|---|---|
| A | 端末内で自動作図、その場で平面図 | 本命 |
| B | クラウド処理 → 図面が返る | 本命。待ち時間と単価を別掲 |
| C | 点群 / メッシュまで出力、作図は CAD で人が行う | 参考枠。DXF 変換までの工数を加算して比較 |
| D | スキャン送付 → **人が作図して納品**する代行サービス | 「手間なく」の観点では有力。必ず入れる |

## 情報源のランク

| 扱い | 中身 |
|---|---|
| 事実 | 自前の実測（同一物件テスト） |
| 事実 | ストアの構造化データ（対応 OS、端末要件、最終更新日、価格、IAP） |
| 事実 | ベンダー公開の**サンプル成果物の実ファイル**（DXF / PDF を実際に開いて確認） |
| 事実 | 学術論文・公的機関の検証・測量業界の実測レポート（**測定条件と誤差の数字があるもの**） |
| 主張 | ベンダーの機能説明・精度表記・価格ページ → `claim_type` を付けて記録 |
| 発見のみ | 比較記事・ブログ・レビュー動画 → 製品名を知るためだけに使う。評価には使わない |

第三者情報の採否は一行で判定する：**測定条件と数字が書いてあるか**。
「高精度でした」は不可。「実測比 平均誤差 ◯mm、n=◯」は可。

## 調査フェーズ

```
A 発見     二次情報OK / 出力は「製品名 + 公式URL」だけ / 5並列
              停止条件: 2ラウンド連続で新規ゼロ
B 立証     1製品 = 1担当 / schema.json を全項目埋める / 一次情報のみ
C 実物回収  サンプル DXF / PDF / 価格ページのスナップショットを実ファイルで取得
D 反証     順位を動かす3主張のみ独立検証
              「DXF が出せる（どのプランで・追加費用は）」
              「面積が自動算出される」
              「実質単価（スキャン単価 / ㎡単価の有無）」
E 監査     unknown の残数を数える。ゼロになるまで B へ差し戻し
──── ショートリスト 5〜6本 ────
F 実測     並列化しない。人間 + 現場担当者本人 + 同一物件（field-test.md）
```

**担当エージェントに点数を付けさせない。** 事実収集のみ。採点は集約側で rubric に従って機械的に行う。
これで担当ごとの甘辛のぶれと、ベンダー主張の事実化を防ぐ。

## 完了条件

- schema.json の必須項目で `unknown` が残っている数 = 0
- 発見フェーズで2ラウンド連続、新規製品ゼロ
- ショートリスト全製品について、同一物件テストの実測値が揃っている

| ファイル | 中身 |

| `candidates.json` | 発見フェーズの母集団（製品名 + URL + 型分類） |

| `ranking.md` | 結論 |
