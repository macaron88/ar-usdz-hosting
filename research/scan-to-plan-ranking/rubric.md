# 採点ルール

エージェントは点数を付けない。ここに書かれた変換だけを集約側が機械的に適用する。

## 1. 足切り（Gate）

1つでも false なら順位表から外し、参考枠へ。**出力形式は足切りにしない**（下記）。

| 条件 | 判定 |
|---|---|
| LiDAR を計測に使用 | `uses_lidar` が true |
| ひとり運用可能 | 三脚・補助者・外部スキャナが必須でない |
| 精度 | 自動生成された出力について、第三者の測定データが見積用途に耐えることを示している |

精度は**自動生成出力**についてのみ問う。ベンダーのサンプル図面は人が整えたものであり、
作り手の技量を測っているにすぎないため、精度の根拠に使わない。

## 1-b. 出力形式は足切りにしない

発注者の判断により、DXF を含む出力形式を足切り条件から外した。

理由: 用途①で必要なのは数量であって特定のファイル形式ではない。BIM 形式で出力されても
そこから平面図は起こせるため、形式で候補を落とすのは不合理である。

したがって出力形式は**併記列**として扱い、種類を網羅的に一覧化する。
ただし「図面も数量も外部に一切出せない」製品は形式選択の問題ではないため、
足切りではなく注記として明示する。

## 2. 順位

Gate を通過したものを、実測した主KPI の昇順に並べるだけ。

```
主KPI = 撮影時間 + 手直し工数     ← 公開情報から推定。実測ではない
```

自前の実測は行わない方針に変更した（時間的制約）。したがって順位は
**公開されている数値と一次情報にもとづく推定**であり、測定値ではない。
この性質は成果物上で明示し、測定値と取り違えられないようにする。

推定の根拠に使えるもの:
- ベンダーが公表する所要時間（例: 60-70m²で約30分）
- 第三者が報告した所要時間・手直し量
- 自動作図の範囲（自動で出る要素が多いほど手直しが減る）
- 数量が自動で出るか（出なければ拾い出しの工数が丸ごと残る）

同値の場合は次の順で並べる：
1. 修正を現場担当者本人ができる（CAD知識不要）方を上位
2. 実質単価が安い方を上位
3. オフラインで完結する方を上位

## 3. 加点・減点は行わない

総合点を作らない。順位は実測工数のみで決まり、
それ以外の情報（精度、費用、日本語対応、待ち時間、出力形式）は
順位表の**併記列**として並べ、トレードオフを読み手に見せる。

理由：重み付き総合点は、重みの根拠が主観になり、最終的に「総合的に判断して1位」に戻るため。

## 4. 参考枠の扱い

Gate 落ちしたものも、落ちた理由を1行で明記して一覧に残す。
特に C型（点群止まり）と D型（作図代行）は、
「DXF 変換 / 納品までの工数と費用」を注記して比較できる形で残す。

## 5. 併記列の記載ルール

| 列 | 書き方 |
|---|---|
| 計測精度 | 実測値を第一とし、なければ第三者検証値、それもなければ「ベンダー主張: ◯」と明記 |
| 図面精度 | 壁の直交性、開口部の自動認識、部屋の閉合。サンプルDXFを開いた所見を1行 |
| 出力形式 | 2D CAD / BIM / 3D / 点群 / 数量 / 閲覧 / 見積特化 に分類して全形式を列挙。有料プラン限定は解放条件を併記 |
| 費用 | 体系（月額/スキャン単価/㎡単価）と、1戸あたりの試算額。試算の前提を脚注に |
| 待ち時間 | 実測。クラウド型のみ |
| 日本 | 契約可否 / 日本語UI / 国内サポート / 請求書払い を4値で |

## 6. 禁止事項

- 出典のない値を埋めない（`unknown` を残す方が正しい）
- ベンダーの精度表記を実測値として扱わない
- fetch に成功していないURLを書かない
- 比較記事・レビュー動画の評価を点数に反映しない
